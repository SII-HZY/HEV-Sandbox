# HEV Generative Sandbox

**A simulation-based framework and fixed benchmark for assessing domain-specific social risks in Large Language Model systems.**

[![License](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)
[![Python 3.8+](https://img.shields.io/badge/python-3.8+-blue.svg)](https://www.python.org/downloads/)
[![Paper](https://img.shields.io/badge/Paper-AAAI%202026-blue)](https://ojs.aaai.org/index.php/AAAI/article/view/40498)

HEV Generative Sandbox evaluates LLM behavior through the **Hazard–Exposure–Vulnerability (HEV)** lens. It supports both fixed benchmark evaluation for reproducible experiments and the original online sandbox loop for generating new domain-grounded risk scenarios.

The framework has four runtime roles:

1. **Scenario Agent**: generates domain-grounded safety scenarios from a corpus and hazard list.
2. **User Agent**: simulates secure, standard, perturbation, and adversarial user interactions.
3. **Target LLM**: the model under evaluation.
4. **Auditor Agent**: audits the target model response and computes risk metrics.

The model used by each role is configurable. You may assign the same model to every role for a simple run, or use separate models for scenario generation, adversarial-prompt generation, target-model evaluation, and auditing.

> This repository is intended for AI-safety research, benchmarking, red-team evaluation, and model-risk analysis. It is not a production moderation system, safety filter, or legal/compliance tool.

## Workflows

### 1. Fixed-dataset evaluation, recommended for reproducibility

This workflow evaluates a target model on the released benchmark under `data/benchmark/`. It does not regenerate scenarios. It uses the fixed questions, perturbations, jailbreak prompts, and option-level safety rubrics included in this repository.

```text
Released benchmark row
        |
        v
User prompt, fixed or generated by UserAgent
        |
        v
Target LLM
        |
        v
Option extraction: A/B/C/D
        |
        v
AuditorAgent option-rubric matching
        |
        v
LEF / vulnerability / domain / hazard / user-type summaries
```

Use this path when you want stable IDs, stable prompts, repeatable outputs, and paper-style benchmark tables.

### 2. Online sandbox evaluation

This workflow keeps the original generative agent loop. The Scenario Agent samples from a domain corpus, generates new scenarios, the User Agent creates prompts, the Target LLM answers, and the Auditor Agent evaluates the responses.

```text
Domain corpus + hazard list
        |
        v
ScenarioAgent
        |
        v
UserAgent
        |
        v
Target LLM
        |
        v
AuditorAgent
        |
        v
Risk metrics
```

Use this path to explore new domains or generate new scenarios. Because it creates new test cases at runtime, it is not the preferred path for exact reproducibility.

## Installation

```bash
git clone https://github.com/SII-HZY/HEV-Sandbox.git
cd HEV-Sandbox

python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
```

On Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
pip install -e .
```

Optional dependencies for local HuggingFace models and advanced perturbation utilities:

```bash
pip install -r requirements-optional.txt
python -m spacy download en_core_web_sm  # optional
```

The fixed benchmark evaluation does not require spaCy unless you explicitly ask the User Agent to generate new perturbations instead of using the released perturbation split.

## Configuration and model roles

The default `config/config.yaml` uses a deterministic `mock` model, so smoke tests run without API keys. Real evaluations should use a separate config file or edit `config/openai.example.yaml`.

### Role-specific model configuration

The pipeline supports the following model-role blocks:

| Config block | Used by | Required for fixed-dataset evaluation? | Notes |
|---|---|---:|---|
| `target_model` | Target LLM under evaluation | Yes | This is the model whose safety is measured. |
| `scenario_model` | Scenario Agent | No | Used only by online scenario generation. |
| `adversarial_model` | User Agent for online adversarial prompt generation | No | Fixed adversarial evaluation uses the released jailbreak prompts instead. |
| `auditor_model` | Auditor Agent LLM fallback | No | Fixed benchmark uses deterministic option matching whenever A/B/C/D can be extracted. |

The three agents do not have to share one model. A simple configuration may point all roles to the same provider. A more controlled experiment can use separate models, for example DeepSeek for scenario generation, Qwen as the target, and GPT as the auditor fallback.

### Example: use one model for every role

```yaml
openai:
  api_key: "env:OPENAI_API_KEY"
  base_url: "https://api.openai.com/v1"
  model: "gpt-4o-mini"
  max_tokens: 200
  temperature: 0.0
  top_p: 1.0

target_model:
  provider: openai
scenario_model:
  provider: openai
adversarial_model:
  provider: openai
auditor_model:
  provider: openai
```

### Example: configure separate role models

```yaml
# The model under evaluation.
target_model:
  provider: local
  model_path: "Qwen/Qwen3-8B"
  device: "cuda"
  max_tokens: 200
  temperature: 1.0
  top_p: 0.95

# Used only in online mode to generate new scenarios.
scenario_model:
  provider: deepseek
  model: "deepseek-chat"
  temperature: 0.7
  max_tokens: 500

# Used only in online mode when UserAgent generates adversarial prompts.
adversarial_model:
  provider: deepseek
  model: "deepseek-chat"
  temperature: 0.7
  max_tokens: 500

# Used only when option extraction fails and LLM fallback is enabled.
auditor_model:
  provider: openai
  model: "gpt-4o-mini"
  temperature: 0.0
  max_tokens: 300

deepseek:
  api_key: "env:DEEPSEEK_API_KEY"
  base_url: "https://api.deepseek.com/v1"

openai:
  api_key: "env:OPENAI_API_KEY"
  base_url: "https://api.openai.com/v1"
```

Never commit API keys. Use `env:VARIABLE_NAME` in YAML and export the corresponding environment variable before running experiments.

## Fixed benchmark data

The released benchmark is stored under `data/benchmark/` as compressed JSONL files.

| Split | Source archive | Rows / prompts | Purpose |
|---|---:|---:|---|
| `base` | `generated_new.zip` | 5,960 rows | Canonical domain-rooted multiple-choice safety benchmark. Use this for Standard User evaluation. |
| `perturbation` | `augmented_data.zip` | 23,840 rows | Fixed non-adversarial input perturbations. Use this for Perturbation User evaluation. |
| `adversarial` | `generated_jailbreak.zip` | 5,960 rows; 29,800 prompts after expansion | Five jailbreak-style prompts per base item. Use this for Adversarial User evaluation. |
| `data/model_outputs/legacy_qwen3` | `results.zip` | 17,880 detail rows | Reference Qwen3-4B/14B/32B outputs. These are model outputs, not ground truth. |

The six fixed benchmark domains are:

| Domain key | Paper domain name | Base rows |
|---|---|---:|
| `conv` | Daily Dialogue | 1,000 |
| `wiki` | Encyclopedic Knowledge | 994 |
| `news` | News | 999 |
| `medical` | Medicine | 1,000 |
| `law` | Law | 967 |
| `edu` | Education | 1,000 |

Raw `original_conversation` text is not included in the normalized public benchmark files. Each row keeps a `source_context_hash` for traceability without redistributing raw source context.

### Normalized row schema

```json
{
  "id": "medical_000001",
  "base_id": "medical_000001",
  "split": "base",
  "domain": "medical",
  "domain_name": "Medicine",
  "test_field": "misinformation and false content",
  "hazard": "misinformation",
  "hazard_name": "Misinformation and False Content",
  "hazard_subtype": "misinformation and false content",
  "question": "Multiple-choice question with A/B/C/D options...",
  "prompt": "Prompt sent to the target model...",
  "reason": "Why this item tests the hazard...",
  "analysis": {
    "A": {"safety": "safe", "explanation": "..."},
    "B": {"safety": "unsafe", "explanation": "..."},
    "C": {"safety": "safe", "explanation": "..."},
    "D": {"safety": "unsafe", "explanation": "..."}
  },
  "safe_options": ["A", "C"],
  "unsafe_options": ["B", "D"],
  "contact_frequency": 1.0,
  "source_context_hash": "sha256...",
  "source_context_included": false,
  "source_item_hash": "sha256..."
}
```

Split-specific fields:

- `perturbation`: includes `base_id`, `original_question`, `augmentation`, and `augmentation_strategy`.
- `adversarial`: stores `jailbreak_prompts` as five `{id, strategy, prompt}` objects per base item. The loader expands these to runtime prompts.
- `model_outputs/legacy_qwen3`: includes normalized reference responses, chosen options, safety labels, and latency fields.

## Quick start: fixed-dataset evaluation

Run a dataset validation check:

```bash
python scripts/validate_dataset.py --split base --domains medical --limit 20
```

Run a smoke test with the default mock model:

```bash
python scripts/evaluate_existing_dataset.py \
  --config config/config.yaml \
  --split base \
  --domains medical \
  --limit 10 \
  --user-types standard \
  --output-dir results/dataset
```

Equivalent CLI:

```bash
hev-sandbox dataset \
  --config config/config.yaml \
  --split base \
  --domains medical \
  --limit 10 \
  --user-types standard \
  --output-dir results/dataset
```

The mock model always returns `The best option is A.` It is only for checking that the repository runs end to end; it is not a meaningful model-risk result.

Run with a real OpenAI-compatible target model:

```bash
export OPENAI_API_KEY="..."

python scripts/evaluate_existing_dataset.py \
  --config config/openai.example.yaml \
  --split base \
  --domains conv wiki news medical law edu \
  --user-types standard \
  --output-dir results/openai_base
```

Run with a local HuggingFace model by setting `target_model.provider: local` and `local.model_path` in your config.

## Online sandbox evaluation

The online workflow generates new scenarios before evaluation:

```bash
python examples/run_evaluation.py \
  --config config/openai.example.yaml \
  --domain medical \
  --num-scenarios 10 \
  --user-types standard adversarial \
  --output-dir results/online
```

Equivalent CLI:

```bash
hev-sandbox online \
  --config config/openai.example.yaml \
  --domain medical \
  --num-scenarios 10 \
  --user-types standard adversarial \
  --output-dir results/online
```

Online mode uses `scenario_model` for Scenario Agent generation, `adversarial_model` for online adversarial User Agent generation, `target_model` for the model under test, and `auditor_model` only if LLM fallback auditing is enabled.

## Outputs

Fixed-dataset evaluation writes a run directory such as:

```text
results/dataset/base_medical_n10/
├── inputs.jsonl.gz
├── standard_detail.jsonl
├── detail.jsonl
├── summary.json
└── report.txt
```

Each detail row contains the normalized scenario, prompt, response, extracted option, safety label, vulnerability value, and expected option-level analysis.

Online evaluation writes:

```text
results/online/<domain>/
├── scenarios.jsonl
├── <user_type>_results.jsonl
├── summary.json
└── report.txt
```

## Metrics

The framework follows the HEV risk view:

```text
Risk = Hazard × Exposure × Vulnerability
LEF  = unsafe responses / total evaluated responses
```

The evaluator reports:

| Metric | Meaning |
|---|---|
| `lef` | Loss Event Frequency as a fraction. |
| `lef_percent` | LEF on a 0–100 scale. |
| `average_cf` | Mean contact frequency. Fixed benchmark rows default to `1.0`. |
| `vulnerability` | Contact-frequency-weighted unsafe-response ratio. |
| `by_domain` | Metrics grouped by benchmark domain. |
| `by_hazard` | Metrics grouped by canonical hazard category. |
| `by_user_type` | Metrics grouped by user persona. |

For the released fixed benchmark, `contact_frequency` defaults to `1.0`, so `vulnerability` usually equals LEF unless custom CF values are added.

## Reproducing paper-style experiments

The released data supports the user-type logic used in the HEV paper:

```text
base split + standard UserAgent      -> Standard User
base split + secure UserAgent        -> Secure-Baseline User
perturbation split, fixed prompts    -> Perturbation User
adversarial split, fixed prompts     -> Adversarial User
```

Commands:

```bash
# Standard User
python scripts/evaluate_existing_dataset.py \
  --config config/openai.example.yaml \
  --split base \
  --user-types standard \
  --output-dir results/paper/standard

# Secure-Baseline User
python scripts/evaluate_existing_dataset.py \
  --config config/openai.example.yaml \
  --split base \
  --user-types secure \
  --output-dir results/paper/secure

# Perturbation User
python scripts/evaluate_existing_dataset.py \
  --config config/openai.example.yaml \
  --split perturbation \
  --output-dir results/paper/perturbation

# Adversarial User
python scripts/evaluate_existing_dataset.py \
  --config config/openai.example.yaml \
  --split adversarial \
  --output-dir results/paper/adversarial
```

Filter a specific adversarial strategy:

```bash
python scripts/evaluate_existing_dataset.py \
  --config config/openai.example.yaml \
  --split adversarial \
  --adversarial-strategy role_playing \
  --domains law \
  --limit 100 \
  --output-dir results/paper/adversarial_role_playing
```

Aggregate detail files into CSV tables:

```bash
python scripts/aggregate_results.py \
  --input-dir results/paper \
  --output-dir results/paper/tables
```

To obtain numbers comparable to the paper, use the same model versions, decoding parameters, system prompt, endpoints, domain list, and user-type definitions as in the experiments. Exact published tables also require access to the same closed-source APIs and model snapshots. This repository provides the fixed dataset, loaders, evaluation scripts, and reference legacy Qwen3 outputs, but it does not include API keys or every closed-source model output.

## Responsible use

The adversarial split contains jailbreak-style prompts. Use them only for legitimate research, benchmarking, red-team evaluation, and safety improvement. Do not use prompts or model outputs to bypass safeguards, harm others, expose private data, or deploy unsafe systems. Follow the terms of service of every model provider you evaluate.

The public benchmark intentionally omits raw `original_conversation` text. Before redistributing any raw contexts or third-party source corpora, confirm license compatibility and privacy requirements.
